# NewsFlow 新闻流自动化处理指令

这是一个自动化流程，用于从配置的网站提取最新内容（包括新闻文章、技术博客、GitHub 热门项目等），生成总结并发送邮件。

## 执行步骤

### 第一步：读取配置文件

读取项目根目录下的 `config.yaml` 文件，获取以下信息：
- `websites`: 网站列表（包含 `name`, `url`, `enabled`）
- `email`: 邮件配置（包含 `recipient_emails`）
- `settings`: 其他设置（如 `max_articles_per_site`）

**注意**：只处理 `enabled: true` 的网站。

### 第二步：提取所有网站的内容链接

对每个启用的网站执行以下操作：

1. 调用 MCP 工具 `extract_links_from_url`，传入网站的 `url`
2. 获取返回的 `links` 数组（包含该网站提取到的所有链接）
3. 分析这些链接，识别出有价值的内容链接：
   - **新闻文章**：技术新闻、行业动态、产品发布等
   - **技术博客**：技术教程、经验分享、技术深度分析等
   - **GitHub 热门项目**：趋势仓库、优秀的开源项目、有特色的项目等
   - **其他有价值内容**：研究报告、产品介绍、工具推荐等
   - 查看链接文本和URL模式
   - 过滤掉导航链接、登录页、用户协议、关于我们等无关链接
   - 保留看起来是有价值内容的链接（包括文章、项目、资源等）
4. 如果配置中有 `max_articles_per_site` 限制，则只保留前N个链接
5. 收集所有网站的内容链接到一个总列表中

**重要提示**：
- 使用 AI 能力智能识别有价值的内容链接，而不是简单的 URL 模式匹配
- 对于不同类型的网站，识别不同类型的内容：
  - **新闻网站**：识别新闻文章、深度报道等
  - **技术博客**：识别技术文章、教程、经验分享等
  - **GitHub Trending**：识别热门仓库、优秀的开源项目等
  - **其他网站**：根据网站特点识别有价值的内容
- 每个链接都要判断其是否为有价值的内容（文章、项目、资源等）
- 记录每个链接的来源网站和内容类型（方便后续追踪）

### 第三步：处理每个内容链接

对汇总后的每个内容链接执行以下操作（无论是新闻文章、技术博客还是 GitHub 项目）：

1. **创建日期文件夹**：
   - 调用 MCP 工具 `create_date_folder`（不传日期参数，使用今天）
   - 确保输出目录存在

2. **读取内容**：
   - **对于文章类内容**（新闻、博客等）：
     - 访问该链接，获取完整的网页内容
     - 提取文章标题和正文内容
   - **对于 GitHub 项目**：
     - 访问 GitHub 仓库页面
     - 提取项目名称、描述、README 内容、Star 数、语言、主要功能等信息
   - 如果访问失败，记录错误并跳过该链接
   - 这里需要的是总结内容，所以没必要再使用一次 extract_links_from_url 工具来读取内容内部的url地址了

3. **生成AI总结**：
   - **对于文章类内容**：基于文章标题和正文内容生成总结
   - **对于 GitHub 项目**：基于项目描述、README、代码特点等信息生成总结
   
   **a. 简短摘要（summary）**：
   - **对于文章类**：生成约200字的中文总结，采用轻松、口语化的表达方式
     - 总结应该包含：文章核心观点、关键信息、主要结论
   - **对于 GitHub 项目**：生成约200字的中文总结，同样采用轻松、口语化的表达方式
     - 总结应该包含：项目用途、主要功能、技术栈、适用场景
     - 语气要自然放松，像介绍一个有趣的工具或项目给朋友一样
   - 语气要自然放松，像朋友聊天一样娓娓道来 🗣️
   - 在合适的位置适当添加表情符号，让总结更生动有趣 😊（比如：👍 表示赞同、💡 表示观点、🚀 表示创新/突破、⚡ 表示快速/重要、⭐ 表示热门项目、💻 表示技术工具等）
   - 避免过于正式和生硬的表达，让读者阅读起来更轻松愉悦 ✨
   
   **b. 详细概括（detailed_summary）**：
   - **对于文章类**：生成详细的内容概括（500-800字），包含以下结构化的部分：
     * **背景信息**：简要介绍文章主题和背景
     * **核心要点**：列出2-5个主要观点（用编号列表或段落形式）
     * **关键信息**：重要的数据、事实、发现或具体案例
     * **影响分析**：这个内容可能带来的影响、意义或启示
     * **结论**：文章的核心结论或主要观点总结
   - **对于 GitHub 项目**：生成详细的项目概括（500-800字），包含以下结构化的部分：
     * **项目背景**：项目解决的问题、应用场景、目标用户
     * **核心功能**：项目的主要功能、特性、技术亮点
     * **技术栈**：使用的编程语言、框架、工具等
     * **项目亮点**：项目的独特之处、创新点、优势
     * **使用建议**：适用场景、使用建议、学习价值
   - 保持轻松、口语化的风格，但内容要更加详细和全面
   - 可以使用表情符号增强可读性，但不要过度使用
   - 确保详细概括是对内容的深入分析，而不仅仅是简短摘要的扩展版本

4. **保存为Markdown文件**：
   - 调用 MCP 工具 `save_markdown_file`，传入以下参数：
     - `title`: 内容标题（格式：中文标题（英文原标题/项目名），用于文件名，会自动进行安全处理）
     - `original_title`: 内容标题（格式：中文标题（英文原标题/项目名），用于Markdown中的"原名"字段）
     - `summary`: AI生成的200字简短摘要
     - `detailed_summary`: AI生成的500-800字详细概括（**必须生成，不能为空**）
     - `url`: 内容原始URL（文章链接或 GitHub 仓库链接）
     - `date`: 今天的日期（YYYY-MM-DD格式，可选）
     - `skip_if_exists`: `true`（如果内容已分析过则跳过）

5. **错误处理**：
   - 如果某个链接处理失败，记录错误信息但继续处理其他链接
   - 不要因为一个链接失败而中断整个流程

### 第四步：发送邮件

当所有链接都处理完成后：

1. 调用 MCP 工具 `send_email_from_date_folder`，传入以下参数：
   - `date`: 今天的日期（YYYY-MM-DD格式）
   - `recipient_email`: 从 `config.yaml` 的 `email.recipient_emails` 读取（支持多个收件人）
   - `subject`: 可选，默认会使用配置中的 `default_subject_prefix`

2. 该工具会自动：
   - 读取今天日期文件夹中的所有Markdown文件
   - 解析每篇文章的信息（原名、AI总结、详细概括、原文链接）
   - 生成格式化的HTML邮件
   - 发送到所有指定的收件人

3. **邮件内容**：
   - 包含所有成功处理的内容（文章、项目等）
   - 每个内容显示：
     * **原标题/项目名**：内容的原始标题或项目名称
     * **简短摘要（AI总结）**：约200字的中文总结，轻松口语化的表达方式
     * **详细概括**：500-800字的详细内容概括（对于文章包含背景信息、核心要点、关键信息、影响分析和结论；对于项目包含项目背景、核心功能、技术栈、项目亮点和使用建议），以折叠形式展示，点击"查看详细概括"可展开
     * **原文链接**：内容原始URL（文章链接或 GitHub 仓库链接）
   - 美观的HTML格式，详细概括默认折叠，方便快速浏览和深入阅读

### 第五步：总结报告

处理完成后，给出一个总结报告：
- 共处理了多少个网站
- 总共提取了多少个内容链接（包括文章、项目等）
- 成功处理了多少篇内容（按类型分类：文章数、项目数等）
- 失败了多少篇内容（如果有）
- 邮件是否发送成功
- 如果有失败的情况，列出失败原因

## 重要注意事项

1. **并发控制**：可以并行处理多个链接以提高效率，但要注意不要超过系统资源限制
2. **去重处理**：如果多个网站提取到了相同的链接，需要去重，只处理一次
3. **错误恢复**：如果中途出现错误，应该继续处理其他链接，不要中断整个流程
4. **日志记录**：记录关键步骤的执行情况，方便排查问题
5. **时间格式**：日期使用 `YYYY-MM-DD` 格式（如 `2025-01-15`）

  - 网站2 (tldr): 提取到 80 个链接，识别出 6 个技术文章
  - 网站3 (GitHub Trending): 提取到 200 个链接，识别出 5 个热门项目
  - 总计: 21 个内容链接（已去重）

[步骤3] 处理内容链接
  - 正在处理 21 个链接...
  - [1/21] ✓ 文章1 - 已保存
  - [2/21] ✓ 项目1 - 已保存

## 技术实现要点

1. **配置文件读取**：直接读取 `config.yaml` 文件（使用 `read_file` 工具）
2. **链接提取**：使用 MCP 工具 `extract_links_from_url`
3. **内容获取**：使用 `read_file` 或网络访问工具获取网页内容（或让 Cursor 通过浏览器访问）
4. **文件保存**：使用 MCP 工具 `save_markdown_file`
5. **邮件发送**：使用 MCP 工具 `send_email_from_date_folder`

## 执行此指令

当用户说"执行newflow"或类似指令时，按照上述步骤顺序执行整个流程。
